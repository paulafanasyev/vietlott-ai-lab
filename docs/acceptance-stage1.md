### Важное разделение по резервному копированию

Внутренний механизм `backup_and_verify` создаёт самодостаточную gzip-копию, восстанавливает её во временные таблицы и сравнивает хеши. Последняя проверка #12 прошла.

Отдельный GitHub Actions workflow должен отправлять дамп в приватный репозиторий `paulafanasyev/vietlott-ai-lab-backups`. Он падает на шаге создания checkpoint:

```text
Thiếu biến môi trường DATABASE_URL
DATABASE_URL:
Process completed with exit code 1
```

В журнале переменная `DATABASE_URL` на этом шаге пуста, поскольку workflow получает её из `secrets.DATABASE_URL_WORKER`. Репозиторий внешних копий пока содержит только README.md — успешного внешнего backup нет.

В workflow добавлена предварительная проверка всех четырёх секретов:
- `DATABASE_URL`
- `DATABASE_URL_WORKER`
- `BACKUP_REPO`
- `BACKUP_REPO_TOKEN`

Проверка сообщает только имена отсутствующих секретов, не раскрывая значения. Следующий запуск требует заполненного `DATABASE_URL_WORKER`; остальные секреты также будут проверены до начала backup.

## Правила сохранности

- Старые строки истории не удалять и не заменять.
- Старые билеты не переписывать после результата; исправления создают новую версию/конфликт по правилам базы.
- NOT PROVEN и CONFLICT не включать в подтверждённую выборку backtest.
- Для Power основные совпадения и дополнительное число показывать раздельно.
- Всегда показывать размер выборки и сравнение с теоретическим baseline.
